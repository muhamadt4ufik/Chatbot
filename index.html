BAB BAB I: PENDAHULUAN

1.1 Latar Belakang

Perkembangan teknologi Kecerdasan Buatan (Artificial Intelligence/AI), khususnya bidang Natural Language Processing (NLP) dan Large Language Models (LLM), telah merevolusi interaksi manusia dengan sistem komputer. Di masa lalu, interaksi komputer terbatas pada menu dan perintah kaku. Kini, melalui NLP modern, mesin mampu memahami teks bebas dalam bahasa alami manusia, menangkap konteks semantik, dan memberikan jawaban secara luwes.

Namun, implementasi sistem chatbot NLP pada web publik kerap menghadapi dua tantangan utama: latensi komputasi inferensi bahasa yang lambat dan kerentanan keamanan kredensial (API Key) pada aplikasi murni sisi klien. Proyek "Taufik AI" dirancang untuk menghadirkan solusi chatbot NLP berkecepatan tinggi dengan akselerasi Groq LPU, didukung arsitektur keamanan serverless proxy pada Netlify Cloud.

1.2 Rumusan Masalah

  • Pemrosesan Bahasa Alami Berkecepatan Tinggi: Bagaimana mengimplementasikan inferensi NLP dengan latensi respons sub-detik agar percakapan terasa interaktif dan alami?
  • Keamanan Kredensial Engine NLP: Bagaimana menyembunyikan API key penyedia model NLP agar tidak dieksploitasi oleh pengguna publik?
  • Resolusi Konteks Bahasa Multibabak: Bagaimana mengelola riwayat percakapan agar asisten memahami acuan kata ganti (coreference resolution) pada dialog beruntun?
  • Personalisasi Gaya Bahasa: Bagaimana mengonfigurasi persona asisten digital dengan karakter ramah berbahasa Indonesia (Taufik AI)?

  • Membangun Antarmuka Chatbot NLP Responsif: Merancang web UI modern yang responsif untuk interaksi percakapan dua arah.
  • Mengintegrasikan Engine NLP Mutakhir: Menghubungkan aplikasi dengan model LLM berkapasitas 120 miliar parameter (openai/gpt-oss-120b) berbasis akselerasi Groq LPU.
  • Mengimplementasikan Serverless Security Proxy: Menyembunyikan kredensial NLP pada environment variables Netlify Functions.
  • Mempublikasikan Sistem di Internet: Mendistribusikan sistem secara global dan gratis melalui platform Netlify.

1.4 Manfaat Proyek

BAB BAB II: TINJAUAN TEKNOLOGI & LANDASAN TEORI NLP

2.1 Konsep Dasar Natural Language Processing (NLP)

Natural Language Processing (NLP) adalah cabang ilmu kecerdasan buatan dan linguistik komputasi yang mempelajari kemampuan komputer dalam memahami, menginterpretasikan, dan menghasilkan bahasa manusia. Dalam arsitektur modern, NLP terbagi menjadi dua sub-bidang esensial:

  • Natural Language Understanding (NLU): Bagian yang bertugas memahami maksud pengguna (intent recognition), mengenali entitas nama/tempat/waktu (named entity recognition), serta mengurai struktur sintaksis kalimat.
  • Natural Language Generation (NLG): Bagian yang bertugas memproduksi kalimat balasan yang koheren, gramatikal, dan relevan dengan konteks percakapan.

2.2 Arsitektur Transformer dan Large Language Model (LLM)

Fondasi model NLP saat ini dibangun di atas arsitektur Transformer yang mengandalkan mekanisme Self-Attention. Mekanisme ini memungkinkan model menimbang bobot hubungan antar-kata dalam sebuah kalimat secara simultan, terlepas dari jarak posisi kata tersebut. Model openai/gpt-oss-120b yang digunakan dalam proyek ini telah dilatih pada miliaran korpus teks multibahasa sehingga memiliki penalaran semantik yang sangat mendalam terhadap bahasa Indonesia.

2.3 Aspek Teknis Penerapan NLP pada Sistem Taufik AI

Dalam proyek Taufik AI, prinsip-prinsip NLP diterapkan pada beberapa layer sistem:

  • Tokenisasi (Tokenization): Teks masukan pengguna dipecah menjadi unit-unit token leksikal sebelum diubah menjadi vektor berdimensi tinggi (embeddings).
  • Rekayasa Prompt & Conditioning (Prompt Engineering): Mengarahkan probabilitas pembentukan teks model melalui System Prompt terstruktur: 'Anda adalah Taufik AI, asisten AI pribadi yang ramah, cerdas, dan membantu. Selalu jawab dengan bahasa Indonesia yang sopan, jelas, dan natural.'
  • Resolusi Koreferensi (Coreference Resolution): Kemampuan mengidentifikasi objek yang dirujuk oleh kata ganti ('dia', 'itu', 'tersebut'). Hal ini diwujudkan dengan menyertakan riwayat 6 pesan terakhir ke dalam context window inferensi.
  • Pengaturan Distribusi Probabilitas (Softmax Temperature): Parameter temperature = 0.7 digunakan untuk mengontrol tingkat entropi dan kreativitas pemilihan kata agar hasil jawaban luwes dan tidak repetitif.

2.4 Komputasi Akselerasi Groq LPU & Serverless Netlify

Groq Language Processing Unit (LPU) menghadirkan kecepatan inferensi token per detik yang jauh melampaui GPU konvensional. Dikombinasikan dengan Netlify Functions sebagai gerbang serverless proxy, seluruh aliran inferensi NLP berjalan aman tanpa mengekspos kredensial ke sisi klien.

1.2 Latar Belakang Masalah dan Solusi yang Dihasilkan

Pada tahap awal pengujian, chatbot mengalami error HTTP 400 akibat digunakannya model lama (llama3-70b-8192) yang telah dinonaktifkan oleh penyedia API. Selain itu, terdapat kebutuhan krusial untuk menyembunyikan API key saat web dipublikasikan secara publik.

Rangkaian solusi yang berhasil diimplementasikan mencakup:

  • Upgrade Engine NLP: Beralih ke model aktif openai/gpt-oss-120b yang sangat fasih berbahasa Indonesia dengan latensi rendah.
  • Mekanisme Fallback NLP: Menyediakan daftar model cadangan (openai/gpt-oss-20b, qwen3.8-27b) untuk menjamin keandalan layanan.
  • Konstruksi Serverless Proxy: Membangun fungsi backend pada Netlify Functions (/api/chat) yang menyembunyikan API key di environment variables.
  • Personalisasi Identitas UI: Menyematkan foto profil Profile.jpg dan menetapkan persona resmi sebagai 'Taufik AI'.

2.2 Analisis Penerapan Natural Language Processing (NLP) pada File Proyek

Penerapan disiplin ilmu NLP tersebar secara terintegrasi pada berbagai file kode program proyek ini. Berikut pemetaan rincinya:

A. Rekayasa Prompt (Prompt Engineering & Conditioning)

Pada file index.html fungsi sendMessage(), diterapkan conditioning berikut:

💡
📌 Kode System Prompt NLP di index.htmlconst messages = [ { role: 'system', content: 'Anda adalah Taufik AI, asisten AI pribadi yang ramah, cerdas, dan membantu. Selalu jawab dengan bahasa Indonesia yang sopan, jelas, dan natural.' }, ...contextMessages];

Instruksi sistem ini bertindak sebagai 'prior probability guidance' pada proses inferensi NLP, mengarahkan gaya bahasa model agar senantiasa sopan, informatif, dan menggunakan bahasa Indonesia yang baik.

B. Penanganan Konteks Dialog Multibabak (Coreference Resolution)

Dalam percakapan alami manusia, seringkali pengguna menggunakan kata ganti ('dia', 'itu', 'tersebut') yang merujuk pada subjek pada pertanyaan sebelumnya. Kode const contextMessages = messageHistory.slice(-6); memastikan konteks riwayat tetap terkirim ke model, sehingga AI dapat melakukan resolusi anaphora dengan tepat.

C. Parameter Pengendali Karakteristik Teks

  • temperature: 0.7: Nilai temperatur optimal dalam NLP. Nilai 0.0 menghasilkan teks deterministik yang kaku, sedangkan 1.0 terlalu acak. Nilai 0.7 memberikan keseimbangan ideal antara akurasi faktual dan keluwesan bahasa.
  • max_tokens: 800: Membatasi output maksimum sekitar 600-800 kata bahasa Indonesia untuk efisiensi komputasi dan kenyamanan membaca pengguna.

BAB BAB I. PENDAHULUAN

1.1 Latar Belakang Proyek

Perkembangan pesat teknologi Artificial Intelligence (AI), khususnya Large Language Models (LLM) dan Natural Language Processing (NLP), telah mentransformasi cara manusia berinteraksi dengan sistem komputer. Antarmuka berbasis teks percakapan (chatbot cerdas) kini menjadi standar baru dalam layanan pelanggan, asisten virtual pribadi, asisten edukasi, hingga automasi pekerjaan sehari-hari. Melalui arsitektur Transformer dan komputasi akselerasi perangkat keras LPU (Language Processing Unit) dari Groq, inferensi LLM dapat disajikan dengan kecepatan ekstrem melampaui 300 token per detik.

Proyek ini bermula dari kebutuhan membangun asisten cerdas berbasis web lokal bernama 'Taufik AI'. Pada tahap inisiasi awal, sistem dibangun dengan antarmuka web client-side (Chatbot web.html) yang berkomunikasi langsung ke endpoint API Groq menggunakan file konfigurasi lokal (config.js). Namun, sistem mengalami kegagalan fungsi (freeze/stuck dan pesan 'Gagal memuat respons') akibat dependensi model lama yang telah didegradasi oleh penyedia cloud, serta adanya keterbatasan fatal dalam keamanan kredensial API key jika ingin dipublikasikan secara daring. Oleh karena itu, diperlukan perancangan ulang sistem yang komprehensif, mulai dari pembaruan model inferensi, perbaikan antarmuka visual, implementasi backend serverless proxy pelindung API key, hingga publikasi ke jaringan cloud publik.

1.2 Tujuan Proyek

Tujuan utama dari pembuatan, perbaikan, dan publikasi aplikasi Taufik AI adalah:

  • Mendiagnosis dan Mengatasi Bug: Mengidentifikasi akar masalah terhentinya komunikasi antara antarmuka web dengan server Groq API dan memperbaikinya.
  • Migrasi ke Model AI Mutakhir: Memperbarui model bahasa usang menuju generasi model performa tinggi (openai/gpt-oss-120b) dengan mekanisme failover multi-model otomatis.
  • Personalisasi Identitas Visual (Branding): Mengubah identitas chatbot generik menjadi 'Taufik AI' dengan menyematkan foto profil personal (Profile.jpg) pada header dan bubble chat.
  • Membangun Arsitektur Serverless Proxy: Menciptakan middleware serverless function berbasis Node.js untuk menyembunyikan API key rahasia di cloud, sehingga sistem dapat diakses publik tanpa risiko pencurian kuota.
  • Menerapkan Natural Language Processing (NLP): Mengintegrasikan pemrosesan bahasa alami mencakup subword tokenization, Natural Language Understanding (NLU), dan prompt engineering berkarakter ramah.
  • Publikasi Cloud Produksi: Mengunggah repositori ke GitHub dan mendeploy ke Netlify hingga aplikasi live 24/7 dan dapat digunakan oleh siapa saja secara gratis.

BAB BAB III. TAHAPAN PERJALANAN PROYEK DARI AWAL HINGGA PUBLISH

Berikut adalah urutan langkah terperinci yang ditempuh selama proses pengerjaan proyek Taufik AI, mulai dari kondisi eror pada file lokal hingga berhasil tayang di internet:

Langkah 1: Menelaah Masalah Awal (Error HTTP 400 Bad Request)

Pada awalnya, pengguna membuka file Chatbot web.html di peramban lokal dengan konfigurasi config.js yang berisi API Key Groq. Ketika pengguna mengetik pesan dan menekan tombol kirim, bot tidak memberikan respons dan menampilkan pesan peringatan 'Maaf, terjadi kesalahan atau API key tidak valid'. Melalui inspeksi network di Browser Developer Tools, teridentifikasi respons HTTP 400 Bad Request dari endpoint api.groq.com. Penyebabnya adalah model 'llama3-70b-8192' telah resmi dinonaktifkan (decommissioned) oleh Groq.

Langkah 2: Migrasi Model ke openai/gpt-oss-120b dan Fallback Otomatis

Untuk memastikan kestabilan jangka panjang, skrip client diperbarui ke model generasi terbaru yang aktif di Groq, yaitu openai/gpt-oss-120b. Selain itu, dibangun algoritma Multi-Model Failover: jika model utama sedang mengalami rate limit atau server busy, JavaScript secara otomatis akan mengalihkan request ke model openai/gpt-oss-20b atau qwen/qwen3.8-27b tanpa membuat sesi obrolan pengguna terputus.

Langkah 3: Personalisasi Branding dan Perbaikan UI (Taufik AI)

Identitas antarmuka dirombak total dari nama generik menjadi 'Taufik AI'. Foto profil pengguna (Profile.jpg) diintegrasikan ke dalam header bar dan badge bot. Ditambahkan pula perbaikan CSS white-space: pre-wrap agar paragraf panjang, poin peluru, dan baris kode yang dihasilkan bot tetap rapi dan tidak bertumpuk.

Langkah 4: Dilema Keamanan dan Perancangan Serverless Backend Proxy

Ketika proyek hendak dipublikasikan secara daring, muncul tantangan keamanan kritis: jika file config.js diunggah ke GitHub, API key rahasia akan terekspos dan disalahgunakan pihak lain. Sebaliknya, jika pengguna diminta memasukkan API key sendiri, situs akan sangat merepotkan orang awam. Solusi terbaik yang dipilih adalah membangun Serverless Proxy (netlify/functions/chat.js). Dengan arsitektur ini, browser hanya memanggil endpoint relatif /api/chat, dan server Netlify yang akan meneruskannya ke Groq dengan menyuntikkan API key dari variabel lingkungan rahasia.

💡
📌 PARADIGMA KEAMANAN: ZERO-CONFIG DENGAN SERVERLESS PROXYArsitektur Serverless Proxy memecahkan dua masalah sekaligus: (1) Menjaga kerahasiaan Groq API Key 100% aman di cloud environment variable, dan (2) Memberikan pengalaman 'Zero-Config' di mana setiap pengunjung dapat langsung mengobrol tanpa perlu membuat akun atau memasukkan API key pribadi.

Langkah 5: Inisialisasi Repositori Git dan Push ke GitHub

File-file proyek ditata ke dalam struktur standar serverless, dibuat file index.html sebagai pintu masuk utama, lalu diunggah ke repositori GitHub muhamadt4ufik/Chatbot:

Langkah 6: Menghubungkan Repositori ke Netlify dan Troubleshooting Edge Access

Repositori dihubungkan ke platform Netlify. Saat pertama kali diakses, muncul form login Netlify (HTTP 401 Restricted Access) yang mengharuskan kata sandi. Masalah ini diselesaikan dengan menavigasi ke Site Settings > Access Management > Visitor Access, lalu mengubah status situs dari Restricted menjadi Public.

Langkah 7: Konfigurasi Environment Variable GROQ_API_KEY

Saat pertama kali dideploy, bot memunculkan pesan 'API Key tidak valid' karena variabel lingkungan belum terisi dengan benar. Terjadi kesalahan pengetikan di mana nama variabel diisi nilai literal dan nilainya tertukar. Setelah diperbaiki dengan konfigurasi Key: GROQ_API_KEY dan Value: gsk_w4CPh... pada Scope 'All scopes', serta dilakukan Trigger Deploy ulang, sistem berhasil 100% online dan responsif.

5.1 Kode Sumber Backend Serverless Proxy (netlify/functions/chat.js)

Source Code
// netlify/functions/chat.js// Serverless Proxy: Menjaga kerahasiaan Groq API Key di Cloud Environmentexports.handler = async function (event, context) {  // Hanya menerima HTTP Method POST  if (event.httpMethod !== "POST") {    return {      statusCode: 405,      headers: { "Content-Type": "application/json" },      body: JSON.stringify({ error: "Method Not Allowed. Gunakan POST." }),    };  }  // Mengambil Groq API Key dari Cloud Environment Variable Netlify  const apiKey = process.env.GROQ_API_KEY;  if (!apiKey) {    return {      statusCode: 500,      headers: { "Content-Type": "application/json" },      body: JSON.stringify({        error: "GROQ_API_KEY belum dikonfigurasi di Environment Variable Netlify!",      }),    };  }  try {    const payload = JSON.parse(event.body || "{}");    const userMessages = payload.messages || [];    // System instruction untuk membentuk kepribadian Taufik AI    const systemPrompt = {      role: "system",      content: "Kamu adalah Taufik AI, asisten virtual cerdas yang diciptakan oleh Taufik. Jawablah dengan ramah, informatif, sopan, dan jelas dalam Bahasa Indonesia."    };    // Forward request ke Groq Cloud API    const response = await fetch("https://api.groq.com/openai/v1/chat/completions", {      method: "POST",      headers: {        "Authorization": `Bearer ${apiKey}`,        "Content-Type": "application/json"      },      body: JSON.stringify({        model: payload.model || "openai/gpt-oss-120b",        messages: [systemPrompt, ...userMessages],        temperature: payload.temperature || 0.7,        max_tokens: payload.max_tokens || 2048      })    });    const data = await response.json();    return {      statusCode: response.status,      headers: {        "Content-Type": "application/json",        "Access-Control-Allow-Origin": "*"      },      body: JSON.stringify(data)    };  } catch (err) {    return {      statusCode: 500,      headers: { "Content-Type": "application/json" },      body: JSON.stringify({ error: "Terjadi kesalahan internal proxy: " + err.message })    };  }};

BAB BAB VI. IMPLEMENTASI NATURAL LANGUAGE PROCESSING (NLP)

Aplikasi Taufik AI menerapkan prinsip-prinsip sains Natural Language Processing (NLP) tingkat lanjut dalam memproses pesan input manusia hingga menghasilkan respons cerdas:

  • 1. Subword Tokenization (Byte-Pair Encoding / BPE): Kalimat pengguna dipecah menjadi token-token sub-kata numerik yang efisien, memungkinkan penanganan kata-kata baru atau istilah slang Bahasa Indonesia tanpa mengalami kendala out-of-vocabulary.
  • 2. NLU (Natural Language Understanding): Model mengekstraksi niat (intent detection) dan entitas penting (named entity recognition) dari pesan pengguna, memahami konteks pertanyaan meskipun diketik secara tidak formal.
  • 3. Multi-Head Self-Attention Mechanism: Lapisan Transformer menghitung bobot keterkaitan matematis antar kata dalam kalimat panjang, memahami relasi rujukan kata ganti (Coreference Resolution) dengan tepat.
  • 4. NLG (Natural Language Generation): Probabilitas token berikutnya diprediksi secara autoregresif menggunakan fungsi Softmax dengan sampling temperature 0.7, menghasilkan kalimat jawaban yang luwes, alami, dan informatif.

Untuk peningkatan kemampuan sistem Taufik AI di masa yang akan datang, direkomendasikan beberapa inovasi pengembangan berikut:
